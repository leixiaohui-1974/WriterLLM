## Major Issues

### M1. Kalman Filter Tuning Justification

**Response**: The reviewer correctly identifies that the Kalman filter covariances were stated without justification. We have added a new paragraph in §3.3 providing a principled derivation:

- **$Q_k$ derivation**: We computed the IDZ→Saint-Venant prediction residual over the 16 ODD scenarios. The residual variance at the nominal operating point is $\sigma^2_{model} = 0.008$ m², yielding $Q_k = 0.01 I$ (rounded up to account for unmodeled dynamics). This is not arbitrary but reflects the measured model mismatch between the IDZ prediction model and the OpenModelica truth model.
- **$R_k$ derivation**: The measurement noise covariance $R_k = 0.64 \times 10^{-6}$ m² corresponds to the measured ultrasonic sensor noise ($\sigma = 0.8$ mm), determined from 10,000 static readings at known water levels.
- **Bandwidth interpretation**: The ratio $Q_k / R_k \approx 15{,}600$ yields a relatively high filter bandwidth (Kalman gain $K \approx 0.85$), meaning the filter trusts measurements more than the IDZ model prediction. This is appropriate because the IDZ model has larger uncertainty (model mismatch) than the sensor noise.
- **Sensitivity analysis**: Added Table 3b showing HiL RMSE as a function of $Q_k$ (four values spanning two orders of magnitude). The results show that HiL RMSE varies from 2.0 mm ($Q_k = 0.01 I$, current tuning) to 2.4 mm ($Q_k = 0.001 I$, over-trusting model) and 2.1 mm ($Q_k = 0.1 I$, under-trusting model). The current tuning is near-optimal, and the RMSE is robust to order-of-magnitude $Q_k$ variation (all values remain below 2.5 mm).

### M2. IDZ Model Validity Domain

**Response**: We have added Table 2b reporting IDZ parameters at three operating points (low, nominal, high) and a new analysis paragraph characterizing the validity boundary:

- **Three operating points**: IDZ parameters identified at $h_0 = 12$ cm (low), 25 cm (nominal), and 38 cm (high). The storage area $A_s$ is constant (prismatic tanks), but the delay $\tau_d$ varies from 7.2 s (high) to 10.1 s (low) and the zero time constant $\tau_m$ varies from 2.4 s (high) to 4.0 s (low). This variation reflects the nonlinear valve characteristic: at low heads, the valve flow is more sensitive to head changes (larger effective delay).
- **Validity boundary**: Closed-loop RMSE remains below 5 mm for all 16 ODD scenarios using the nominal IDZ model (single linearization at $h_0 = 25$ cm). The worst-case closed-loop RMSE is 3.8 mm (scenario S11, $h_0 = 35$ cm, step −10 cm). Extrapolating, the MPC with nominal IDZ parameters would exceed 5 mm RMSE at approximately $h_0 = 7$ cm — below the ODD lower bound of 10 cm. Thus, the single-linearization IDZ model is adequate for the defined ODD.
- **Gain scheduling**: For the dual-tank system, gain scheduling is not necessary because the ODD range [10, 40] cm results in modest parameter variation ($\tau_d$ varies by ±15% from nominal). However, for field-scale systems with wider operating ranges, gain-scheduled IDZ models would be needed. This is noted in §7.8 (Limitations).

## Minor Issues

### m1. Equation (2) Valve Model Regularization

**Response**: The OpenModelica implementation uses a regularized square root function: $\sqrt{|\Delta h| + \epsilon}$ with $\epsilon = 10^{-6}$ m, which avoids the derivative singularity at $\Delta h = 0$. This is OpenModelica's standard `Modelica.Fluid.Utilities.regRoot` function. Stated explicitly in §3.1.

### m2. Table 3 QP Solver Clarification

**Response**: Clarified in §5.1. The auto-generated C code uses an active-set QP solver generated by Simulink Coder's `mpcActiveSetSolver` function — this is a standalone C implementation that does not depend on MATLAB's `quadprog`. The solver is compiled into the Arduino binary. Table 3 now lists "quadprog (MiL) / mpcActiveSetSolver (SiL, HiL)" for clarity.
