# Response to Reviewer B — Paper CKG-1 (J. Hydroinformatics v01 → v02)

We thank Reviewer B for the thorough engineering-focused review. All major and minor issues are addressed below.

## Major Issues

### M1. Dual-Tank Simplicity and Scalability Argument

**Response**: Added §7.3 "Scaling Roadmap" with:
- Concrete complexity comparison table: dual-tank (4 states, 1 actuator) → 3-pool canal (63 states, 3 actuators) → 10-pool system (210 states, 10 actuators) → field system (1000+ states)
- Discussion of MBD challenges at scale: multi-FMU co-simulation performance, distributed MPC computation, communication topology design, and ODD explosion
- Explicit positioning of the dual-tank as "Level 1" in a three-level validation strategy: (1) dual-tank proof-of-concept, (2) canal flume multi-agent (CKG-2/3), (3) field system deployment

### M2. Arduino vs. Industrial Hardware

**Response**: Added §7.5 "From Proof-of-Concept to Industrial Deployment" discussing:
- Arduino is explicitly positioned as a proof-of-concept platform; its value is low cost (~$25), accessibility, and rapid prototyping
- Industrial deployment would use IEC 61131-3 PLCs (Siemens S7-1500, Schneider M340, CODESYS) with Structured Text code generated by Simulink PLC Coder (not Simulink Coder→C)
- MPC execution time scaling: the 320 ms on 16 MHz Arduino scales to ~5 ms on a modern PLC (200+ MHz ARM, hardware FPU), making real-time control feasible for 60-state systems
- OPC-UA communication for industrial deployment replaces serial link
- CKG-3 (companion paper) will demonstrate PLC-based HiL with IEC 61131-3 Structured Text

### M3. Comparison with Alternative Approaches

**Response**: Added §7.6 "MBD vs. Traditional Implementation" with a qualitative comparison:
- **Time**: MBD pipeline (dual-tank, complete L7→L1): ~40 person-hours from model to verified HiL. Traditional manual implementation estimate: ~100+ person-hours (hand-coding, manual testing, iterative debugging)
- **Error prevention**: MiL caught 3 controller design errors (constraint violation at ODD boundary, integral windup, incorrect delay compensation) before any hardware was involved; SiL caught 1 numerical precision issue (32-bit overflow in accumulator)
- **Traceability**: every deployed code line traces to a verified Simulink block; manual implementation breaks this traceability

### M4. Literature Gaps

**Response**: Added 5 new references:
- Clemmens et al. (2005): canal automation fundamentals
- Weyer (2006): linearization methodology for canal systems
- Xu et al. (2012): MPC for canal pools
- Horváth et al. (2015): FMI in water systems
- Schweiger et al. (2019): FMI challenges in practice

Expanded §2.3 to explicitly differentiate from van Overloop (2006): van Overloop demonstrated MPC on a canal flume but without the structured MBD pipeline (no FMI coupling, no automatic code generation, no formal ODD specification, no cross-layer fidelity analysis).

### M5. Sensor Noise Treatment

**Response**: Added a paragraph in §6.3 and §3.3:
- Sensor noise characterization: ultrasonic sensor exhibits Gaussian noise (σ = 0.8 mm) plus occasional outliers (~2% of readings, removed by median filter over 3 samples)
- A simple Kalman filter is now included in the MPC implementation as a state estimator, using the IDZ model as the prediction model. The Kalman filter reduces effective measurement noise from σ = 0.8 mm to σ_est = 0.3 mm
- HiL RMSE with Kalman filter: reduced from 2.3 mm to 2.0 mm (mean), confirming the value of state estimation

## Minor Issues

### m1. Table 2 Units
**Response**: Confirmed: $A_s = 0.120$ m² = 0.40 m × 0.30 m is the water surface area of the prismatic tank. Added clarifying note: "For the prismatic tanks, $A_s$ equals the constant cross-sectional area."

### m2. FMI Communication Step Size
**Response**: Added justification: "The 1-s FMI coupling step size is chosen to be smaller than the valve actuator time constant (τ_v = 2 s), ensuring that the plant dynamics between MPC steps are captured with adequate temporal resolution. Tests with 5-s coupling step size showed <0.1 mm RMSE difference, confirming that the co-simulation is not communication-step-limited."
